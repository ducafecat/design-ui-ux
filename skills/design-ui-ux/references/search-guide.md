# 检索与规范记录

需要查样式、颜色、字体或交互细节时读取。检索用于支持主流程，不替代真实样稿选择、风格确认或成品验收。

## 环境与入口

脚本只依赖 Python 标准库。先检查 `python3 --version`；没有 Python 时使用本技能的详细规范继续设计，并说明未执行本地数据检索，不自行安装系统软件。

先定位包含本技能 SKILL.md 的实际目录，以下以 `<skill-dir>` 表示；执行前替换为带引号的实际路径，不依赖当前工作目录或固定安装位置。例如本仓库路径是 `skills/design-ui-ux`，安装后也可能位于 `.agents/skills/design-ui-ux`。

## 按需要选择一种检索

新建设计需要整体设计系统时，使用已选参考、业务和访谈结果组织关键词：

```bash
python3 "<skill-dir>/scripts/search.py" "gaming social warm dark" --design-system -p "项目名"
```

针对单一问题使用明确领域；默认技术的实现规范选择 `html-tailwind`。用户明确指定其他技术时，选择工具实际支持的对应参数；不支持时说明缺口，使用适用的规范或可靠文档，不退回默认技术覆盖用户要求。以下为默认技术的示例：

```bash
python3 "<skill-dir>/scripts/search.py" "keyboard focus modal" --domain ux
python3 "<skill-dir>/scripts/search.py" "responsive form navigation" --stack html-tailwind
```

查询保持一个主要意图，通常用 2–5 个有效关键词和一个场景约束；脚本数据以英文为主，查询词可以使用英文，向用户的说明保持中文。不要把整个验收清单拼成一次检索。

| 参数值 | 用途 |
|---|---|
| `product`、`style` | 产品模式、整体风格与适用范围 |
| `color`、`typography`、`google-fonts` | 配色、字体组合及字体信息 |
| `ux`、`web` | 交互与界面行为；返回原生平台建议时筛选网页适用部分 |
| `icons` | 图标语义与视觉选择；实现使用独立 SVG，不照搬与本稿无关的导入代码 |
| `landing` | 需要宣传或营销页面时的内容结构 |
| `chart` | 需求中存在图表时的类型与表达 |
| `gsap` | 确实需要复杂动效时的候选思路；简单反馈使用 CSS 即可 |

## 检索结果如何使用

- 检查返回领域、首条结果和目标设备是否匹配，不因命中关键词就采纳。
- 空结果或不相关时，用更窄的查询或明确领域重试一次。仍无有效结果时说明没有验证匹配，使用详细规范和设计判断，不捏造来源。
- 数据库的样式、配色、字体和代码只是建议；用户已确认的方向优先。不能因为游戏类默认返回紫色，就覆盖用户选定的黑橙配色。
- 搜索脚本输出的是候选，不会检查当前 HTML 的字号、对比、点击区域或链接。必须另做浏览器验收。
- 可用 `--variance`、`--motion`、`--density` 的 1–10 数值调节候选倾向；它们是检索参数，不是强制问用户的新题目。
- 不把私密业务数据、凭据或个人信息放进外部搜索、截图说明或持久化规范。

## 可选：持久化检索规则

用户需要跨页面复用设计系统时，可在主流程交付文件之外保存规则。必须先验证结果与选定方向一致，再执行：

```bash
python3 "<skill-dir>/scripts/search.py" "gaming social warm dark" --design-system --persist -p "项目名" --output-dir "项目根目录"
```

规则位于 `design-system/<项目标识>/MASTER.md`。页面确有差异时加 `--page "页面名"`，保存页面覆盖规则。

- 复用时先读主规则，再读对应页面规则；页面规则只覆盖其明确声明的差异。
- 已存在的规则先读取，保留其有效决策，不用 `--force` 盲目覆盖。更新范围以用户本次需求为准。
- 此技术性规则文件不替代最终单文件 HTML 内用户可浏览的样式说明视图。只需单次设计稿时，不额外创建这套目录。
