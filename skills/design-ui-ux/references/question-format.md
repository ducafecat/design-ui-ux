# 逐题提问格式

在需要用户选择或风格确认时读取。每次只问一题，等待回答后推进依赖步骤；已知答案和已明确授权的事项不重复确认。

每题明确标注 `【单选】`、`【多选】` 或 `【确认】`，题干单独一段，选项逐行排列，不将选项挤在一句话中。选项使用稳定编号，每项写明名称及具体效果或适用场景；推荐项在对应选项后标注“（推荐）”，确认题不预选同意。优先使用支持对应题型的交互提问工具；工具不支持多选或无法完整展示选项时，使用文本格式。工具已展示问题时，正文不重复提问。文本格式如下：

```text
【单选】这次输出哪一端的设计？

1. 移动端
2. PC 端

回复一个编号，也可以直接描述你的选择。
```

```text
【多选】你希望保留哪些视觉特点？

1. 大标题
2. 温暖配色
3. 图片氛围

回复一个或多个编号，例如：1、3；也可以补充自己的想法。
```

```text
【确认】是否同意以上风格方案，并开始制作设计稿？

1. 同意，按此方案开始制作
2. 不同意，需要修改（请说明修改点）

回复 1 或 2，也可以直接说明意见。
```

确认题需明确本次确认的对象与同意后的下一步动作；未回复、默认选中或仅浏览预览页均不视为同意。示例内容随业务调整，保留题型、分行选项和回复说明。

**单选与多选的选项完整性**：尽可能列全当前业务下有意义的不同方向，不固定限制为 2–3 项，也不只给推荐方向。每项采用“名称：具体视觉效果、行为或适用场景”的形式，让用户能理解差异；有必要时补充取舍，避免仅列抽象风格词。选项多时可按类别分组，编号保持唯一连续，仍只围绕当前一个问题。单选各项应能明确区分；多选应说明可组合关系、互斥限制，以及“都不选”如何表达。允许用户自由补充或表示暂不确定；工具自带自由输入时不重复添加同义选项。只列适用且不重复的方向，不为凑数量加入无关选项；目标端等范围明确的问题保留实际可选项。上述短示例只演示排版，不代表实际选项数量上限。
