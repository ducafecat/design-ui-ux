# HTML + Tailwind 详细设计规范

制作预览页和最终业务设计稿前读取。默认适用于 HTML + Tailwind 浏览器设计稿，不把原生平台专有能力当成网页已实现的功能。用户指定其他技术或格式时，仅沿用适用的视觉、交互与可访问性原则，代码写法、尺寸单位、组件及验证工具遵从目标平台，不机械套用网页规则。以用户确认方向和实际可用性为依据。

## 0. 单文件实现与运行

- 默认最终程序为一个自包含 `design/index.html`。全部功能页面与样式说明通过文件内视图和 hash 路由切换，不另建详情页或样式说明 HTML。
- 制作时可使用 Tailwind CLI、源 CSS 和脚本模块；最终把编译 CSS 放入 `<style>`，JavaScript 放入内联 `<script>`，SVG 直接内嵌。不得用 CDN Tailwind、外链样式、脚本或字体作为成品运行依赖。
- 位图、必要字体及演示音视频编码为 data URL 或从内嵌数据生成 Blob URL；压缩并合理控制体积，交付说明实际大小。Blob URL 在不再使用时释放；素材来源记录须内置，外部来源链接不自动加载。
- JSON 业务数据、配置、来源与验收记录一并内嵌。可使用 JavaScript 对象或 `<script type="application/json">`，不得依赖相邻 JSON、相对 fetch 或外链 JSON 才能使用和查看记录。记录入口使用文件内视图；解析时处理无效数据，序列化时转义 `<` 等可提前闭合脚本的内容，原始 JSON 通过 `textContent` 显示。内部构建用 JSON 不计入用户运行依赖。
- 使用文件内真实链接，例如 `#list`、`#detail?id=...`、`#style-guide`，保证复制链接、刷新、浏览器返回与新标签打开仍进入同一文件的正确视图。不要只靠点击拦截掩盖指向其他 HTML 的 href。
- 视图卸载时移除监听、断开观察器、取消定时任务、停止媒体，防止重复导航后叠加副作用；异步回调不得修改已卸载视图。返回时恢复必要筛选、浏览位置和焦点。
- 核心演示不使用依赖 HTTP 的相对 fetch、外部 JSON 或模块导入；显式真实服务接入遵从用户需求并标注网络边界。以复制到空目录后的 `file://` 浏览验证自包含性，HTTP 服务仅作为补充预览。

## 1. 视觉与信息层级

- 每个页面突出一个主要任务；次要操作在尺寸、位置、颜色上从属，但仍可识别。
- 排版、配色、图片和材质共同表达所选气质。不要同时混用没有关联的拟物、玻璃、像素等风格。
- 先保证关键内容可读、可操作，再添加装饰；装饰不能压住内容、抢占主要入口或降低对比。
- 以 CSS 变量或 Tailwind 主题定义语义颜色：背景、表面、正文、次要文本、主操作、边框、错误、成功和焦点。组件复用变量，不到处散落相近色值。
- 只实现需求中的明暗主题。双主题确有需求时分别测试，不能直接反色或从一个主题推定另一个主题合格。

## 2. 字体与颜色

- 正文默认 16px，行高约 1.5–1.75；辅助标签可用 12–14px。核心内容不低于 12px，不用 7–10px 正文塞满屏幕。
- 手机输入框字体至少 16px，避免聚焦时自动放大。桌面密集数据可以采用清晰的 14px 层级，须说明用途，不能影响可读性。
- 中文正文使用可读的系统字体或实际加载成功的字体；个性字体主要用于标题，必须有中文回退。自托管字体按需加载并设置 `font-display`。
- 字号与字重有明确层级，数字可用等宽样式；长文控制行宽，不能把中文字符数与英文字符数机械等同。
- 普通正文及辅助文本对比至少 4.5:1；大字至少 3:1（约 24px 常规字或 18.7px 粗体）。有意义的图标和必要控件边界至少 3:1。
- 测量实际组合的前景和背景；渐变、图片、透明表面和弹窗遮罩也要检查。不能仅靠“看起来还行”声称达标。
- 状态不只靠颜色：错误加说明、选中加标记、在线状态加文字或可访问名称。

## 3. 布局与响应式

- 使用 `width=device-width, initial-scale=1`，允许用户缩放。布局采用弹性宽度、网格和明确最大宽度，不把固定桌面画布硬缩到手机。
- 以 4px/8px 为间距基础，明确组件内距、组间距和区块间距。相同层级保持节奏，不能把所有间距设成同一数值。
- 移动端优先主内容和触控操作；PC 端利用更宽网格、侧栏与键盘交互，不强行套底部手机导航。
- 手机布局验证 375px、430px 与横屏；桌面布局验证 1024px、1440px。只承诺实际测试过的设备范围。
- 使用 `min-height:100dvh` 或可适配容器处理浏览器栏变化；固定顶栏/底栏需预留内容空间，并处理 `env(safe-area-inset-*)`。
- 手机输入法打开、横屏或高度不足时，输入框、关闭与主要操作仍应可达；避免固定最小高度把底部操作推出视口。
- 桌面可并排展示手机样稿，但实际手机视图必须以真实字号和尺寸工作，不能把展示比例当成实际点击尺寸。
- 长标题允许换行；长 URL 使用可断行策略，弹性子元素允许收缩。标签集合优先换行，必要的省略需提供可访问的完整内容。
- 默认避免页面级横向溢出与无意义的嵌套滚动。聊天日志、弹窗等确需独立滚动时验证触控、焦点与滚动边界。

## 4. 图标、图片与素材

- 默认使用 Phosphor 的独立 SVG，也可用同一套 Heroicons SVG；保持轮廓、填充、描边和尺寸一致，不引入前端框架包来使用图标。
- 图标在 16/20/24px 等统一尺度上选用。结构性导航与系统操作不用 Emoji 代替；聊天正文可保留用户语境中的表情。
- 装饰图标隐藏于辅助技术；纯图标按钮有可访问名称，状态按钮暴露选中、展开或按下状态。
- 有意义图片提供准确替代文本，装饰图片用空 `alt`；声明尺寸或宽高比。首屏关键图片优先加载，其余按需延迟。
- 图标、标志优先矢量；摄影与插画按合适分辨率压缩，可用 WebP/AVIF。不要把照片也强制转换成矢量。
- 使用真实品牌时采用可确认的素材与比例，示例符号不能冒充官方标志。记录外部素材来源，不把照片人物当成真实示例账户身份。
- 素材原件可本地保存作为证据；最终单文件须内嵌实际使用的素材。字体优先系统回退或内嵌字体，不依赖外链加载。无法取得素材时采用可内嵌的替代方案并说明限制。

## 5. 交互与反馈

- 用原生 `button`、链接、输入框等语义控件；点击目标有按下、选中或加载反馈。不能只写 `cursor-pointer` 却没有实际行为。
- 手机主要控件以至少 44×44 CSS px 命中区为设计目标，保持足够间隔；小图形可扩大命中区，但不能与相邻操作重叠。不要把原生 pt、dp 和网页 CSS px 混用。
- PC 控件仍需易点选、可键盘操作，悬停不能作为唯一入口。拖动、滑动操作有点击和键盘替代方式。
- 筛选、排序和搜索必须改变真实展示结果；考虑无结果、清空筛选与组合状态。不要点击后只弹无关提示。
- 异步操作有适当加载与失败反馈；请求中避免重复提交。原型未接服务时清楚写演示，不假装请求成功。
- 表单有可见标签、必填说明与就近错误提示；保留用户已输入的信息。占位符不能代替标签。
- 本地存储可能不可用或含无效数据：校验读取值，捕获写入异常，给出不误导的反馈。
- 聊天、评价等用户文本用安全文本渲染，不把未经转义的输入注入 HTML。不要把设计稿内容实际发送给外部用户。
- 导航与返回路径稳定；手机底部顶级导航通常不超过 5 项，不在弹窗中承载全部主要导航。

## 6. 键盘与可访问性

- 键盘可走通主要任务，焦点顺序符合视觉顺序，有可见焦点；固定栏与遮罩不能把焦点控件藏住。
- 弹窗有名称、关闭方式和焦点管理；关闭后回到仍可见且合适的触发位置，不能聚焦已隐藏元素。
- 页面导航切换后按需把焦点移到新内容标题，不能持续留在被隐藏的旧页面。
- 标题层级与内容结构清楚；图标按钮、输入框、搜索、分类和状态有正确名称与语义。
- 计数和完成反馈按需使用状态区域，避免每一帧、每次输入都重复播报；未读数量更新需保留上下文。
- 支持文字放大与浏览器缩放，检查长文本；不禁用粘贴、密码管理或系统快捷键。
- 自动轮播有暂停方式，重要内容不能只在悬停时可见。只声明实际验证过的可访问性，不以普通检查代替完整审计。

## 7. 动效与性能

- 动效表达反馈、层级和连续性，不为炫技增加复杂度。统一少量时长与缓动变量，常见反馈约 150–250ms，可按实际距离调整。
- 优先改变 `transform`、`opacity`，减少布局抖动；快速重复点击可中断或替换过渡，不能依赖动画结束事件才能进入正确状态。
- 尊重 `prefers-reduced-motion`：减少装饰位移、视差、闪动与自动动画。基本交互仍须可用。
- 图片预留空间，避免异步内容跳动；避免大量无用途脚本。高频搜索或滚动计算确有必要时节流或防抖。
- 长列表出现可测量性能问题时再分页或虚拟化，不因条目超过任意数量就一律引入复杂实现。

## 8. 图表与数据界面（出现时使用）

- 图表类型服务于比较、趋势或比例任务；标明时间、单位、图例和数据来源。示例数据明确标注。
- 多系列不能只靠颜色区分，补充线型、图案或直接标签。复杂图表提供文本概述或表格。
- 交互提示支持键盘与触屏，不能依赖鼠标悬停；有空数据、加载和错误状态。
- 小屏减少拥挤刻度或调整布局，不能简单缩小整张图使文字不可读。

## 9. 样式标准说明的核对方式

样式说明作为最终 HTML 内的一个视图，并提供进入和返回入口，不单独生成 `style-guide.html`。从实际实现提取颜色变量、字体层级、间距、断点、圆角、阴影和动效值。列出主要组件的默认、悬停、按下、焦点、选中、禁用，以及实际存在的加载/错误状态。

用真实组件样例展示这些约定；说明图片与图标来源、主题范围、已测试视口及演示能力边界。设计改变后同步更新，不能把参考模板的数值当成本项目已经实现的标准。
